# 文档声明沿用五态，不新增第六态，也不使用自证雾

为了对抗文档腐化，我们把文档中可被机器核对的引用建模为文档声明，让它和代码区域一样拥有证据状态。我们决定不新增 `doc-fog-returned` 状态：引用对象在声明之后发生改动、或已不存在时，声明直接进入 `fog-returned`，因为回雾的本义是“证据落后于它所描述的对象”，而 ADR-0001 把唯一的警示橙留给了这一种信任退化。文档声明也不使用自证雾：代码与文档在同一次提交中一起修改是应当鼓励的同步行为，不是独立预期缺失的信号。

## Considered Options

- **新增第六态 `doc-fog-returned`**：要么和回雾争用唯一的警示橙，要么为信任退化再引入一种颜色，两者都违背 ADR-0001。
- **只在被引用的代码区域上附加“文档过时”标记**：存在性校验、执行证据和 Agent 修改后的验收都失去落点。

## Consequences

- 文档声明计入独立的 `Doc Trust Score`，不改变代码 `Trust Score` 的含义。
- 状态枚举不变；文档回雾通过主体类型和 Finding 标签与代码回雾区分。
- 两次解析都失败的形似标识符不视为声明，避免把普通术语误报为回雾。
