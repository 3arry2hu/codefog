# 采用「雾优先」五态模型与单色相顺序色阶 + 单一互补橙配色

代码覆盖率工具传统上使用红绿灯配色（绿色代表高覆盖率，红色代表未覆盖），这会让大面积的“已覆盖代码”占据视觉焦点，并掩盖仅被执行但无实质断言的“伪覆盖”。我们决定采用**雾优先（Fog-first）五态模型**（`Verified`、`Weak Evidence`、`Self-proof Fog`、`Fog`、`Fog Returned`），在视觉上将 `Verified` 退化为极浅灰背景（`#EBEFF4`），按 OKLCH 单色相石板蓝顺序色阶编码未验证程度（`#BCCCE2` → `#6E88AA` 斜纹 → `#1D3656`），并将全画面唯一的高饱和互补警示橙（`#BD4900` + `RETURNED` 标签）保留给紧急的信任退化事件 `Fog Returned`。

## Considered Options

- **传统红绿热力图或光优先模型（Fog / Faint / Bright / Lighthouse）**：高置信度区域最亮（亮橙/金色），未验证区域为深灰。问题在于大仓库中 80% 以上的已验证区域会形成强烈视觉噪音，违背“先看到哪里不可信”的目标。
- **Radix 石板灰 + 蓝色雾 + 橙色警示**：蓝色在主流设计系统（如 GitHub Primer）中代表“链接/可点击/选中”语义，容易将未知风险误读为交互焦点，且浅蓝弱证据大面积出现时过于抢眼。
- **OKLCH 石板灰顺序色阶 + 实心警示橙 `Fog Returned`（已采纳）**：遵循 90-8-2 面积法则与前注意属性（Preattentive Pop-out），依靠明度差（12:1）区分未验证与已验证，依靠唯一色相 + 文字标签 + 斜纹实现色盲友好的双重编码。
